# Разграничение доступа в SQL Server

Здесь я собрал восстановленные материалы своей практики №8 по безопасности систем баз данных. Для реконструкции я использовал текст отчёта и скриншоты. Столбцы `employees` восстановлены из `image3.png`; остальные таблицы — минимальная новая схема по перечню сущностей из отчёта. Данные синтетические.

В этой работе я рассматриваю разграничение прав бухгалтера: он читает финансовые данные, но не изменяет их и не получает доступ к отдельной закрытой схеме.

## Выполнение

В своей локальной SQL Server, через SSMS, последовательно выполнить:

1. `00_create_database.sql` — создать отдельную БД `PortfolioSecurityLab`. Если она уже есть, скрипт откажется её перезаписывать.
2. `01_schema.sql` — создать схемы, таблицы и примеры.
3. `02_permissions.sql` — создать роль и пользователей **WITHOUT LOGIN**, назначить права.
4. `03_verify.sql` — выполнить разрешённые SELECT и проверить реальные отказы INSERT/UPDATE/DELETE и чтения закрытой схемы.

Пользователи WITHOUT LOGIN нужны для изолированной проверки через `EXECUTE AS USER`: они не демонстрируют вход на SQL Server по паролю. Серверные логины и реальные пароли не создаются.

## Исправление исходного примера

На скриншоте роль `sysadmin` назначается одному login, а `db_denydatareader` — другому пользователю. Запрет чтения не ограничивает `sysadmin`. В новом сценарии бухгалтер не является администратором; роль получает SELECT на схему `lab` и запрет изменения данных.

Проверки выполняются от лица пользователя, а не через административный SELECT, который сам по себе ничего не доказывает о правах бухгалтера.

## Статус
