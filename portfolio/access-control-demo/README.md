# Контроль доступа в ASP.NET Core

В этом проекте я публикую восстановленную версию своих практик по дисциплине «Распределённые информационно-аналитические системы» №5, №15–16. Сохранившийся REST-листинг вынесен в `extracted/*.txt`; это справочный исторический код, он не компилируется вместе с приложением.

Моя задача — показать работу приложения с пользователями и REST API. В новой реализации `reader` читает записи, `admin` создаёт, изменяет и удаляет. Пароли передаются при входе и проверяются по хешу `PasswordHasher`; готовых паролей в коде нет. Есть CSRF-проверка, ограничение попыток входа и валидация данных. Изменение интерфейса не позволяет обойти серверную проверку ролей.

Исторический `/login/{username}` выдавал токен без проверки пользователя. В опубликованной версии я отказался от такого маршрута. Для этой реконструкции я выбрал **cookie**, а не JWT; точное восстановление обеих схем из отчётов не заявляю. Учебные примеры ASP.NET Core в исходных отчётах основаны на материалах [METANIT](https://metanit.com/sharp/aspnet6/); при подготовке портфолио я использовал помощь ИИ для реконструкции и исправлений.

## Запуск

Нужен .NET SDK 10. Из корня репозитория:

```powershell
dotnet build portfolio/access-control-demo/AccessControlDemo.csproj
./portfolio/access-control-demo/run-demo.ps1
```

Скрипт запросит два временных пароля длиной не менее 12 символов. Открыть `http://127.0.0.1:5087`. Имена пользователей: `admin`, `reader`. Если локальная политика запрещает запуск `.ps1`, можно задать переменные `DEMO_ADMIN_USER`, `DEMO_ADMIN_PASSWORD`, `DEMO_READER_USER`, `DEMO_READER_PASSWORD` в текущем терминале и выполнить `dotnet run --project portfolio/access-control-demo --urls http://127.0.0.1:5087` с `ASPNETCORE_ENVIRONMENT=Development`.

## Проверка

```powershell
python tests/check_access_control.py
```

Проверка запускает собственный процесс на свободном локальном порту и завершает его. Выполнена успешно: 401 без входа и при неверном пароле, 403 для записи от reader, 400 без CSRF и при неверных данных, CRUD администратора, флаги HttpOnly/SameSite, выход, ответ 429 при повторных попытках.

## Границы примера

Пользователи и записи хранятся в памяти. Сеансы ограничены 15 минутами. Выход удаляет cookie из браузера; централизованный отзыв скопированной cookie не реализован. Ограничитель входа общий для процесса. MFA, аудит и восстановление пароля не реализованы.

HTTP разрешён для локального режима Development. В остальных режимах cookie имеют Secure; необходим HTTPS. Ключи защиты cookie сохраняются в игнорируемом `data/keys` без настроенного внешнего шифрования: для рабочего развёртывания требуется отдельная конфигурация хранения ключей. Это локальный учебный стенд.

Проверка выполнялась через HTTP-клиент; отдельная визуальная проверка браузером не проводилась.
