## Публикация

Если репозиторий создаётся вручную, откройте [создание репозитория](https://github.com/new), выберите свой аккаунт, укажите название и видимость Public. Для загрузки уже подготовленной Git-истории не добавляйте README, .gitignore или лицензию на сайте: они уже подготовлены локально. [Инструкция GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository).

`publish-dist/university-security-portfolio.zip` — отдельный архив с отобранными публикационными файлами. Чистый каталог находится в `github-ready/ready-to-publish/university-security-portfolio`. Там нет исходного учебного архива, паролей, ключей cookie, временных файлов и результатов сборки. Каталог `github-ready/university-security-portfolio` использовался для локальных проверок; для ручной загрузки выбирайте именно чистую копию или ZIP.

При работе через Git из этого подготовленного каталога:

```powershell
git init -b main
git add .
git commit -m "Add university information security portfolio"
# Вместо YOUR-LOGIN укажите подтверждённое имя аккаунта.
git remote add origin https://github.com/YOUR-LOGIN/university-security-portfolio.git
git push -u origin main
```

Если каталог уже содержит `.git`, повторная инициализация и повторный коммит не нужны: сначала проверьте `git status`, `git log -1` и `git remote -v`. Не используйте `--force` для существующего репозитория.

Авторизация выполняется через GitHub или Git Credential Manager. Не вставляйте токены в чаты, команды, URL репозитория или файлы проекта. Если защищённая среда помощника не имеет доступа к авторизации, те же команды можно выполнить в обычном терминале на своём компьютере.

## Оформление профиля

1. В **About** репозитория заполните описание и Topics из примера выше.
2. Закрепите репозиторий в профиле через **Customize your pins**.
3. В bio профиля можно написать: `РТУ МИРЭА · Информационно-аналитические системы безопасности · Ищу стажировку в ИБ`.
4. После первой загрузки откройте **Actions** и проверьте результат workflow **Portfolio checks**. До его завершения нельзя считать удалённые проверки пройденными.
5. Для резюме используйте ссылку прямо на этот репозиторий. Контакты указывайте только те, которые хотите сделать публичными.

Если нужен отдельный README профиля, можно создать репозиторий с именем `VIEGA7`, точно совпадающим с логином владельца, и перенести туда адаптированный текст из [PROFILE_DRAFT.md](PROFILE_DRAFT.md). Это отдельное изменение аккаунта; текущий проект не перезаписывает существующий профиль.
